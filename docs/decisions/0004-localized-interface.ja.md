# 管理インターフェイスの多言語設計

2026-09-09。利用者の多言語対応指示に基づく。
[公開コマンド方針](0003-management-interface.ja.md)と同じ操作・認可・監査を使う。
実装と検証範囲は[多言語対応](../../native/localization.ja.md)を参照。

対象はDebian 13が提供する全言語とする。glibcのSUPPORTED全locale/encoding組と、
localechooserの有効な言語選択肢を正本に固定して追跡する。日本語・英語だけを
製品の対応言語と定義しない。locale、メッセージ翻訳、font/shaping、入力method、
画面と読み上げの受入を別の条件として管理し、fallbackを翻訳完了と数えない。

## 表示と操作の分離

言語は利用者の表示設定である。翻訳を操作要求、署名入力、権限判断、catalog、WAL、
復旧状態、結果コードの一部にしない。CLI・TUI・GUIは同じ構造化された結果を受け、
各利用者の言語で表示する。管理serviceのlocaleをクライアントごとに変更しない。

コマンド名、短縮オプション、属性キー、パッケージ名・版・architecture、パス、hash、
修正ID、内部状態識別子、機械処理形式のキーは翻訳しない。保存値・署名対象の文字列を
Unicode正規化して書き換えない。日付・数値の表示整形と解析・比較は分離する。
機械処理形式ではASCII数値、固定の区切りとescaping、UTCを含む版付き仕様を使う。
表示言語によって完了・結果不明・未実行の区別や終了値を変えない。

## 翻訳単位と供給

英語原文をmsgidとするGNU gettextを使用する。翻訳はPO、配布物はコンパイル済みMO、
抽出元はPOTで管理する。短い断片を連結せず、完全な文章と名前付きプレースホルダーを
使う。訳文側で語順を変更できるようにし、値を翻訳キーへ混ぜない。
同じ単語でも意味が異なる場合はpgettextの文脈を使う。複数形はngettextで扱い、
「1か、それ以外か」という分岐を画面側に固定しない。

翻訳カタログは製品の一部として配布・検査する。作業ディレクトリ、利用者指定の
catalogパス、環境変数のTEXTDOMAINDIR/LOCPATHを特権処理の翻訳供給元にしない。
翻訳の欠落・破損は英語へフォールバックする。翻訳のために操作を再実行しない。
再生成の差分、未翻訳、fuzzy、引数不一致、制御文字をCIで失敗させる。

## 言語選択

メッセージlocaleは非空のLC_ALL、LC_MESSAGES、LANGの順に選ぶ。
LANGUAGEはそのlocaleがC系でない場合に、翻訳の優先順として使う。
未対応言語では次の候補、最後に英語へフォールバックする。
NiaではC、POSIX、C.UTF-8、C.utf8を英語固定の表示として定義する。
既存のプロセス全体のlocaleや数値書式は変更しない。

territoryと@modifierを維持し、localeのencoding指定だけをメッセージcatalogの検索から
外す。@latin等の文字体系や@valencia等の変種を無条件に落とさない。@euroは通貨の
指定として共通訳を使用できる。中国語の繁体字・簡体字は別catalogとし、香港は繁体字、
シンガポールは簡体字の明示したfallbackを持つ。必要な変種が未翻訳なら英語へ戻す。
全言語のrelease gateは未翻訳の対象が一つでもある間は失敗する。

GUI/TUIの言語設定は表示層へ渡す。languageタグとPOSIX localeの変換は一箇所に集約し、
UI言語をcron、版比較、パス解決、署名検証の入力解釈へ流用しない。

## 画面と入力

GUIはtoolkitの双方向文字処理・フォントfallback・accessibilityとlayoutを使用する。
固定pixel幅やASCII文字数で訳文を切らない。RTLでは適切な部品配置を使う一方、
パス・版・hash・コマンドを文字列反転しない。画面倍率、長い訳、入力method、
screen reader、キーボード操作、低解像度を受入対象にする。

TUIの配置はterminal cell幅とgrapheme clusterを考慮する。結合文字やemojiを途中で切らず、
色だけで状態を区別しない。固定の文字幅を前提にするPythonのlen/整列書式を使わない。
現在のCLIはlabel/value行で表示し、多列TUIの幅計算を実装済みとは扱わない。
未信頼データの端末制御文字やbidi overrideは可視化するが、自然言語の結合に必要な
ZWNJ/ZWJを一律に消さない。元データのバイト列は維持する。

確認画面の選択は内部の操作識別子へ束縛し、訳文を認可データにしない。
破壊的操作の既定は取消とし、EOF、閉じる、無効な入力、割込みを同意と解釈しない。
キー表記・確認入力の対応も言語ごとに仕様化する。対話機能の未実装を翻訳で補わない。

## 適合と検証

参照インターフェイスとの適合は、C localeでの応答仕様と言語別の表示を分けて受入する。
全言語で同一の入力・状態・終了値・出力先・副作用・復旧結果を照合する。
未対応locale、翻訳破損、長い表示、日本語・RTL・結合文字・非UTF-8端末・非TTYも含める。
翻訳と構文試験だけで、未接続の管理器・TUI・GUIの受入を完了扱いにしない。
