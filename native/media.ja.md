# ローカルDEB媒体の索引と一覧

`inutoc DIRECTORY`は、指定した一つのディレクトリにある`.deb`を原本のまま検査し、
`.toc`へ決定的な媒体索引を作る。再帰探索、展開、maintainer script実行はしない。
省略時のディレクトリは`/usr/sys/inst.images`。成功時は出力せず終了値0となる。
失敗時は共通の翻訳済み診断をstderrへ出し、終了値1となる。

`installp -l -d DIRECTORY`は翻訳した見出しで媒体内容を表示する。
`installp -L -d DIRECTORY`と`geninstall -L -d DIRECTORY`は同じ機械処理用の一覧を返す。
一覧は元DEBを毎回読み直すため、`.toc`を改変して署名済み・導入済みと主張できない。
索引がなければ原本から一覧を計算し、読取操作では索引を書き込まない。
既存索引と原本が違う場合は`NIA-E-MEDIA-STALE`で拒否し、`inutoc`による再作成を案内する。

索引のschemaは`org.niaos.media-index/v1`。各DEBのファイル名、サイズ、SHA-256、
原本のpackage/version/architecture、説明、controlのhash、効果・トリガー宣言を保持する。
供給認証・実行許可・導入済み状態を示す三つのflagはfalseで固定する。
時刻や作業ディレクトリの絶対パスを含めず、ファイル名順で正規化する。
同じ内容を再作成しても索引のinodeを置換しない。同一package/version/architectureの重複は拒否する。

## 保存と同時変更

ディレクトリを成分ごとにリンクを辿らず開き、保持したfdに相対なIOを使用する。
ディレクトリinodeのflockで一覧同士は共有、索引作成は排他とする。
索引作成は現在の実効UIDが所有し、group/worldから書込みできないディレクトリに限る。
DEBと索引にはサイズ上限・通常ファイル確認・読取前後と名前のinode/属性照合を行う。
ディレクトリ一覧も再検査し、操作途中に観測した変化を拒否する。

新しい索引は排他的に作った一時ファイルへ書込み・fsyncしてからrenameし、親もfsyncする。
既存の未知形式、リンク、途中で置換された索引を上書きしない。
rename後の親fsync失敗は終了値1で完了不明を伝える。この時、完全な新版が見えることはあり得る。
再実行は原本から検査し直す。プロセスが強制終了した場合の一時ファイルは権威を持たない。
予約を無視する書込みをすべて阻止する仕組みではなく、導入時には別途、原本hashと供給認証を再確認する。

## 入力と表示の範囲

対象は平坦なディレクトリ内のamd64/all DEB。原本読取器の対応形式に限る。
一つ128 MiB、合計64 GiB、最大4,096 DEB、ディレクトリ全体65,536項目、索引・表示8 MiBまで。
下位ディレクトリのパッケージは探索しない。非DEBの文書等は索引へ含めない。

`-L`の開発中のnative列は`PACKAGE:LEVEL:ARCHITECTURE:DESCRIPTION:FILE:SHA256`。
先頭行はこの列名を`#`から出力し、各値はUTF-8のpercent encodingを使用する。
安全なASCIIの英数字と`/+.-_~`は保持する。版のepochにあるコロンは`%3A`、
percent記号は`%25`となり、復号で原本を完全に戻せる。localeで列名や値を変えない。
元の版を別形式に書き換えたり、存在しない導入状態・ライセンス状態を列へ埋めたりしない。
このnative表示形式は参照した管理体系との完全な応答互換性の受入をまだ満たさない。

媒体一覧の成功は供給認証、依存解決、更新の事前検査、効果完了ではない。
稼働管理器、全DEB効果、lppmgrの保持条件を伴う移動・削除、新ISOへの配布は未接続である。
