# 状態領域・ロールバック・回復

`contracts/state-domains.json`は領域分割の規約であり、自動でpartitionを削除・再構成するスクリプトではない。
ソフトウェアとその所有権DBは同じ導入世代へ照合する。DBだけ戻す、/usrだけ戻す操作を正当化しない。
SUSEのBtrfs/Snapperを利用しても、ESP・TPM・外部DB・ネットワーク機器の状態まで一つのsnapshotにはならない。

`/var`は一括して「全部除外」や「全部巻戻し」にしない。package state、設定派生物、業務データ、
監査、秘密情報、回復記録それぞれに所有者・耐久条件・保管期限を設定する。
回復候補のRPMと設定基準、initramfs、module、鍵信頼の関係を保持する。
Secure Boot回復用の署名済みimageは現在の失効方針で検査する。古い信頼を復活させない。

管理サービス自身の失敗、設定検査器の不在、source inventoryの不明を、新しい変更への拒否として扱う。
既に整合して稼働しているサービスを、通信不通だけで停止させない。
一方、書込み所有権の競合やデータ破損の証拠がある場合は、既存の停止/fencingプロトコルで隔離する。

rollbackには新しい認可とデータ互換性検査を要求する。設定の旧schemaへ戻せることと、
その間に進んだDBを旧ソフトが読めることは別である。
本構成のファイル・etcd・サービス・DBを跨ぐ大域ACIDは提供しない。
各所有者のdurabilityと相関したintent/receipt/復旧を扱い、効果が不明なら再送しない。
